# go_docker

## docker_test

运行服务前，通过进程环境提供 AES-256 key。变量值必须是标准 Base64 编码，解码后恰好
32 字节。新密钥可在受控终端中生成并直接保存到个人密码管理器，不要写入仓库：

```bash
cd docker_test
openssl rand -base64 32
ENCRYPTION_KEY='<从个人秘密存储注入>' go run .
```

仓库中的 `docker_test/config/config.yaml` 仅保留无密占位，不存放可用 key。

当前文件格式是 `GDK1` 版本化 AES-256-GCM 信封，每次加密使用独立随机 nonce；篡改、错误
密钥以及未带版本的旧 CFB 密文都会失败关闭。存储密文解密只接受服务生成的随机 token，不接受
任意文件路径；token 通过 POST 表单传递，不会出现在 URL 查询串或默认访问日志中。两种解密
接口均直接返回禁止缓存的下载响应，不在磁盘落明文副本。服务默认只监听
`127.0.0.1:8888`，不对局域网或公网开放。

旧实现曾把加密材料提交到公开历史，且 legacy CFB 没有认证保护。旧 key 与旧密文必须视为
失效；本版本不会自动迁移或解密旧格式。公开历史清理、访问认证、密文生命周期与部署加固仍是
独立门禁，因此该仓库目前只适合作为个人实验代码归档，不应直接用于生产或敏感数据。
